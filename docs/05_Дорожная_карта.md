# HopeBackup — дорожная карта

Проектный документ (архитектура, каталог продуктов, коннекторы, ноды, облака) — в Claude Docs,
«Ковчег — система резервного копирования и восстановления». Здесь — что уже работает и что дальше.

## Сделано в 0.9.6

- **«Серверы и ВМ»: смена пользователя и способа входа.** При смене пользователя (или адреса) и переходе с пароля на
  ключ сохранённый пароль больше не мешает сохранению («адрес или пользователь изменились — введите пароль или
  ключ заново»): заново нужен только секрет выбранного способа входа. Хранится только он — пароль при входе по
  ключу и ключ при входе по паролю удаляются. Пароль sudo прежнего пользователя или адреса сбрасывается (новому он
  не подходит и туда не отправляется); парольная фраза ключа сохраняется — она никуда не передаётся.

## Сделано в 0.9.5

- **Исключение продуктов из репликации площадки целиком.** На закладке «Репликация» — переключатель «Передавать
  этот продукт при репликации площадки». Снапшоты, блоки и WAL исключённого продукта на принимающие площадки не
  уходят, остальные продукты — уходят. По умолчанию исключён «Образ машины по SSH».
- **Готовые qcow2 — только по явному включению.** Площадки «Образов qcow2», включённые не на закладке
  «Репликация» (перенесённые из параметров 0.9.2), при обновлении выключаются.
- **Быстрая репликация с исключениями.** Блоки читаются пачками — один запрос к узлу на до 256 блоков (узел
  0.9.5+; со старым узлом — по одному, как раньше), pack-файлы собираются и отправляются в фоне. Замер (512 МБ,
  RTT 50 мс): было 6,3 с против 3,7 с у обычной репликации, стало 4,1 с; если сервер далеко и от исходной
  площадки — было 13,2 с, стало 5,3 с (обычная — 5,6 с).
- **Возврат к обычной репликации без повторной передачи.** Перед передачей pack-файла проверяется его индекс:
  если все блоки уже на принимающей площадке — файл не передаётся (в замере: из 32 pack-файлов переданы только
  4 с блоками исключавшегося продукта, 28 пропущены).
- **Каналы VPN при параллельных заданиях:** канал, проверенный другим заданием за последние 15 с, берётся без
  проверки; не ответивший канал перепроверяется через 3 с, прежде чем переподниматься, — передачи других заданий
  по нему не обрываются.
- **Уведомление в карточке образа** (и в журнале копии): репликация образа остановлена или не настроена — и
  ссылка на закладку «Репликация»; уведомление можно скрыть.

## Сделано в 0.9.2

- «Образы qcow2»: **площадка не выбирается** — всегда та же, что у источника (оттуда сервер берёт копию для
  сборки); куда отправлять готовые qcow2 — отдельным полем. Источник обязателен; экземпляры с другой площадкой
  выравниваются при запуске сервера; при переводе источника на другую площадку сборка идёт оттуда. Источник
  нельзя удалить, пока из него собирают образы.
- **«Сколько места понадобится»** в формах «Образ машины по SSH» и «Образы qcow2»: до первой копии — по описи
  дисков машины (размер дисков, занято на файловых системах; кнопка «Снять опись машины», если её нет), после —
  точно по последней копии. Рядом — свободное место в хранилище площадки, в локальной папке сервера и на
  площадках для qcow2, с отметкой «не хватит». Пояснение: к серверу управления должен быть подключён диск
  большого объёма.
- Блок «Найдено на серверах — не защищено» сворачивается (запоминается в браузере).
- Исправлено: панель в выпуске 0.9.1 была собрана с номером 0.9.0, и после обновления страницы оставалось
  предупреждение «эта страница — ещё панель 0.9.0». Теперь выпуск пересобирает панель и проверяет номер.

## Сделано в 0.9.1

- **«Образы qcow2» собирает и конвертирует только сервер HopeBackup** — в своей локальной папке на подключённом
  диске (например, `/mnt/data/hopebackup-images`); агент для этого продукта не выбирается (экземпляры 0.9.0,
  назначенные агенту, переводятся на сервер). Путь к копии: машина → по SSH → сервер HopeBackup (блоки в
  репозиторий с дедупликацией) → сборка qcow2 в локальной папке сервера → готовый qcow2 на удалённую площадку.
  В форме — список подключённых дисков сервера со свободным местом; новую папку на системном диске продукт
  сам не создаёт.
- **Готовые qcow2 — на удалённые площадки** (узлы HopeBackup): после каждой сборки набор отправляется на
  выбранные площадки и лежит там открыто, рядом с репозиторием (`<данные узла>/images/<репозиторий>/<экземпляр>/<набор>/`),
  — его можно сразу подключить к гипервизору ЦОД. Первый раз передаётся всё содержимое, дальше — **только
  изменившиеся участки по 4 МиБ**: qcow2 собирается с закреплённой раскладкой (`preallocation=metadata`,
  файл разрежённый), узел копирует у себя прошлый набор, сервер сравнивает суммы участков и шлёт отличия
  (zstd), затем суммы сверяются целиком. Обрыв канала — повтор с места остановки. Старые наборы на площадке
  удаляются (хранить N), только если у площадки задан токен очистки. Кнопка «Отправить на площадки» —
  повторить отправку вручную; на карточке площадки — какие наборы там лежат и путь к ним.
- Узлу площадки для приёма образов нужна версия 0.9.1 (обновите HopeBackup-02 через «Узлы управления»).

## Сделано в 0.9.0

- Новый продукт **«Образ машины по SSH»**: образ дисков физической или виртуальной машины по SSH без агента —
  сервер управления (или агент) запускает на машине `hopebackup disk-read`. Диски читаются блоками по 4 МиБ;
  тома LVM — согласованно через снимок (`lvcreate -s`), остальные разделы на ходу (с предупреждением),
  подкачка — нулями. Безопасный путь чтения: штатные средства (снимок LVM, обычное чтение файла устройства и
  снимка), без низкоуровневого доступа к блочным устройствам. Хранение — как у прочих продуктов: дедупликация
  (запись фиксированными блоками со ссылками на блоки прошлой копии), шифрование, репликация, политика хранения.
  В каждую следующую копию уходят только изменившиеся блоки.
- **Развёртывание «Развернуть ВМ»**: создание ВМ с параметрами источника (vCPU, память, BIOS/UEFI, сетевые
  карты с теми же MAC) на Proxmox VE, libvirt/KVM, oVirt/zVirt, OpenStack; плюс выгрузка файлов образа
  (qcow2, vmdk streamOptimized, vhd, raw) в каталог — потоком, нулевые блоки «дырами».
- Продукт **«Образы qcow2» (доп. канал)**: по расписанию собирает готовые файлы образов в каталог из последней
  копии, хранит последние N наборов, проверяет свободное место до создания.
- **Скачивание .qcow2** в панели — только для администратора: размер показывается до скачивания, ссылка
  одноразовая, каждое скачивание пишется в журнал аудита.
- Исправлено перед выпуском: «Образы qcow2» при хранении последних N удаляют только свои подкаталоги наборов
  (раньше — любые каталоги в указанном месте); оценка места учитывает временный raw на время сборки;
  недособранные наборы и файлы скачивания удаляются; без новой копии источника набор не пересобирается;
  продукты образов можно назначить серверу управления («Кто выполняет» → «Сервер управления»), и его копии
  запускают репликацию и очистку по хранению; в формах машина и источник выбираются из списка, а форма
  «Образов qcow2» показывает оценку места до создания; в «Серверы и ВМ» — кнопка «Образ дисков».
- Следующим выпуском для развёртывания: VMware vSphere, XCP-ng, Nutanix, OpenNebula.
