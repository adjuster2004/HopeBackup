# HopeBackup — аварийное восстановление (потеря площадки)

## Схема

```
 ЦОД-1 (основная)                          ЦОД-2 (резервная)                 Облако
 ┌───────────────────────┐   каталог       ┌────────────────────────┐
 │ сервер управления S1  │ ─────────────▶ │ сервер управления S2   │
 │   (активный, эпоха N) │   (30 с, HMAC)  │   (принимающий)        │
 └──────────┬────────────┘                 └───────────┬────────────┘
   агенты ──┤ копии                                    │
 ┌──────────▼────────────┐   репликация    ┌───────────▼────────────┐   репликация   ┌──────────────────┐
 │ площадка A (узел N1)  │ ─────────────▶ │ площадка B (узел N2)   │ ─────────────▶ │ Yandex Object    │
 └───────────────────────┘ (как есть,      └────────────────────────┘                │ Storage / AWS S3 │
                            без удалений)                                            └──────────────────┘
```

* **Каталог** (площадки, коннекторы, экземпляры, расписания, цели, пользователи, агенты) активный узел
  передаёт принимающим каждые 30 секунд и сразу после изменений.
* **Данные копий** — репликацией площадок: всё, что попадает на площадку A, копируется на B (и в облако)
  после каждой копии и каждые N минут (сегменты WAL). Данные уже зашифрованы — принимающей площадке ключи
  не нужны. Удаления не повторяются: у принимающей площадки своя очистка по тем же политикам хранения.
* **Агенты** знают все узлы управления и сами переключаются на активный.

## Подготовка (один раз)

1. На резервной площадке: узел хранения (`deploy.cmd … node`) и сервер управления (`deploy.cmd … server`).
2. На активном узле: **Площадки → Добавить площадку** — узел ЦОД-2 (или бакет S3). Затем у основной
   площадки: **Изменить → Принимающие площадки** — отметьте ЦОД-2, «догонять каждые 10 мин». Пароль
   репозитория у ЦОД-2 — тот же, что у основной; репозиторий на ней создаст первая репликация
   («Синхронизировать сейчас»), вручную его не создают.
3. На активном узле: **Узлы управления → Пригласить принимающий узел** — адрес активного узла
   (`https://s1:4443`), код приглашения.
4. На новом сервере ЦОД-2: войдите его собственным паролем Administrator → **Узлы управления →
   Подключиться к активному узлу** → код, адрес этого узла (`https://s2:4443`). Каталог узла заменится
   каталогом активного; дальше входите учётными записями активного узла.
   **Если с S2 до S1 доступа нет** (например, VPN до ЦОД-2 поднимает сам S1 коннектором): на S2 —
   **Узлы управления → Подготовить к подключению с активного** (код с адресом S2), на S1 — **Узлы управления →
   Подключить по коду узла** → код, коннектор до ЦОД-2. S1 сам заходит на S2 и передаёт каталог; дальше
   синхронизация идёт тем же путём, а коннектор поднимается перед каждой отправкой.
5. На S2: **Узлы управления → Доступ к площадкам с этого узла** — например, площадка B доступна с S2
   напрямую по `https://127.0.0.1:8443` без коннекторов.
6. Проверка: на S2 в мастере восстановления выберите площадку-источник B и сделайте пробное
   восстановление на сервер по SSH или новую ВМ.

Порты: агенты → все узлы управления (4443/tcp); активный узел → принимающие (4443/tcp, синхронизация);
активный узел → все площадки (репликация идёт через сервер управления и его коннекторы).

## Основная площадка потеряна

1. Убедитесь, что активный узел действительно недоступен (не сетевой сбой на минуту).
2. Откройте панель S2 (вход — учётной записью активного узла). Вверху — «Принимающий узел…».
3. **Узлы управления → Принять управление.** S2 становится активным (эпоха N+1): запускаются расписания,
   агенты в течение минуты переключаются на S2.
4. **Площадки → площадка A → «перевести экземпляры сюда»** у принимающей площадки B: экземпляры начинают
   писать на B, A становится принимающей для B (догонит изменения, когда вернётся).
5. **Мастер восстановления**: площадка-источник B → точка или момент времени → цель: сервер по SSH,
   сервер с агентом или новая ВМ (Proxmox, VMware, Yandex Cloud, AWS) → «Установить PostgreSQL той же
   версии» для чистой ВМ → запуск.
6. Когда основная площадка вернётся: прежний активный S1 получит каталог с эпохой N+1 и сам станет
   принимающим (в журнале аудита — `cluster_demote`). Агенты на него не вернутся: его эпоха меньше.

## Сервер управления недоступен, а машину нужно поднять сейчас

Если для машины настроены «Образы qcow2» с копированием на площадку, на её узле лежит готовый файл, который
подключается к гипервизору без HopeBackup. Путь — на карточке площадки («Образы qcow2»), по умолчанию
`<данные узла>/images/<репозиторий>/<экземпляр>/<набор>/<диск>.qcow2` (на HopeBackup-02 — под
`/mnt/data/hopebackup/images/…`). На Proxmox VE этой площадки:

```
qm create 9001 --name srv-restore --memory 4096 --cores 2 --net0 virtio,bridge=vmbr0 --scsihw virtio-scsi-single
qm disk import 9001 /mnt/data/hopebackup/images/<репозиторий>/<экземпляр>/<набор>/sda.qcow2 local-lvm
qm set 9001 --scsi0 local-lvm:vm-9001-disk-0 --boot order=scsi0
qm start 9001
```

Для машины с UEFI добавьте `--bios ovmf --efidisk0 local-lvm:1`. Берите последний полный набор (каталог без
префикса `.part-`). На libvirt/KVM: `virt-install --import --disk path=<файл>.qcow2,format=qcow2 …`.

## Что важно

* **Пароль репозитория** — тот же для всех реплик (репозиторий копируется целиком с его конфигурацией).
  Без него восстановление невозможно ни с одной площадки.
* **Принимающий узел не принимает изменений** настроек (их перезапишет синхронизация) — только просмотр,
  проверки и восстановление на сервер по SSH или новую ВМ. Восстановление на сервер с агентом — после
  «Принять управление» (агенты подключаются только к активному узлу).
* **RPO при потере площадки** = интервал репликации (по умолчанию 10 минут для сегментов WAL) плюс
  время последней синхронизации. Для меньшего RPO уменьшите интервал у площадки.
* **Объектное хранилище с Object Lock** как последняя линия: копии в нём нельзя удалить до срока даже с
  ключами администратора — защита от шифровальщика, добравшегося до обеих площадок.
* Без сервера управления: `hopebackup repo --url https://узел-B:8443 --token … --fingerprint … list`
  (или `--url s3://бакет/префикс --s3-endpoint …`) и `restore --plugin …` — репозиторий самодостаточен.
