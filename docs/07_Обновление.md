# Обновление HopeBackup на работающих серверах

Документ — для серверов, где «Ковчег» уже установлен и работает: сервер управления, принимающие узлы
управления, агенты, узлы площадок. Первая установка описана в [01_Установка.md](01_Установка.md).

## 1. Способы обновления

| Что обновляется | Из панели («Безопасность → Обновления») | Скриптом установки |
|---|---|---|
| Сервер управления | Да, начиная с версии 0.8.1: архив выпуска или онлайн по манифесту, автоматический откат | Да, любая версия: `sh hopebackup-install.sh server` |
| Принимающий узел управления | Да — в панели этого узла | Да: `sh hopebackup-install.sh server` |
| Агенты | Да, агенты 0.8.1 и новее: кнопкой в блоке «Агенты», сборка берётся из комплекта сервера | Да: `sh hopebackup-install.sh agent`, `deploy.cmd` или «Серверы и ВМ → Установить агента» |
| Узлы площадок | Нет | Да: `sh hopebackup-install.sh node` |

**Скриптом обязательно обновляются:**

- серверы до версии 0.8.1 — в них ещё нет раздела «Обновления»; первый раз после этого — скриптом, дальше — из панели;
- машины без systemd и без OpenRC;
- узлы площадок.

Данные, настройки, пароли репозиториев, токены, сертификаты и адреса служб при обновлении сохраняются. Копии на площадках не затрагиваются: формат репозитория совместим между версиями.

## 2. Порядок

1. **Принимающие узлы управления** (если есть) — по одному.
   - Принимающий узел хранит копию каталога, которую присылает активный.
   - Узел прежней версии не знает новых разделов каталога и не сохранит их.
   - Если обновить сначала активный, а потом потерять площадку, при «Принять управление» часть настроек новой версии пропала бы (например, проекты переезда).
2. **Активный сервер управления.** Вместе с ним обновляется комплект сборок для машин (x86_64 и ARM64, glibc и musl).
3. **Агенты** — из раздела «Обновления» (все устаревшие одной кнопкой) или скриптом.
   - Агенты прежней версии продолжают работать с новым сервером: копирование, WAL и восстановление идут как раньше.
   - Новые возможности плагинов появляются после обновления агента.
4. **Узлы площадок** — в любое время. Пока узел перезапускается, агенты ждут его до 10 минут и продолжают копию.

## 3. Перед обновлением

- **Задания.** Посмотрите раздел «Задания».
  - Копии на агентах переживают перезапуск сервера: агент сохранит итог и отправит его позже.
  - Задания самого сервера прервутся: восстановление по SSH и на новую ВМ, опись машин, репликация площадок. Дождитесь их окончания.
- **Переезды.** Не обновляйте сервер, пока у проекта переезда идёт переключение.
- **Резервная копия каталога данных сервера.** Нужна для отката на прежнюю версию:

  ```sh
  sudo tar czf /root/hopebackup-server-$(date +%F).tgz -C /var/lib/hopebackup server
  ```

  В копии — `state.json` (каталог: площадки, экземпляры, пароли репозиториев), сертификат панели, история заданий и журнал аудита. Храните копию как секрет.
- **Установленная версия:** `hopebackup --version` или `sh /tmp/hopebackup-install.sh status`.

## 4. Из панели

Раздел «Безопасность → Обновления» — только для администратора.

### 4.1. Источник пакета

**Из архива (закрытый контур).**

1. Загрузите `hopebackup-<версия>-linux.tar.gz` из папки `bin/release` комплекта поставки. Файл передаётся
   частями по 4 МБ: при обрыве связи (VPN, нестабильный канал) часть повторяется сама, а если связь пропала
   надолго — кнопка «Продолжить загрузку» продолжает с того же места, уже переданное хранится на сервере.
   В конце сервер сверяет SHA-256 всего файла с подсчитанной в браузере.
2. Панель проверит пакет:
   - контрольные суммы всех сборок (`dist/*.sha256`);
   - сборку для этого сервера — исполняемый файл Linux нужной архитектуры;
   - пробный запуск `--version` от непривилегированного пользователя;
   - номер версии (не ниже 0.8.1).
3. Панель покажет SHA-256 файла — сверьте его с `SHA256SUMS` выпуска.

Можно загрузить и одну программу `hopebackup.gz`. Тогда обновится только сервер, а комплект для агентов останется прежним.

**Онлайн.** Укажите адрес манифеста — JSON на сервере обновлений или внутреннем веб-сервере организации:

```json
{
  "stable": { "version": "0.9.0", "url": "hopebackup-0.9.0-linux.tar.gz",
              "sha256": "<sha256 архива>", "notes": "Что нового" },
  "beta":   { "version": "0.10.0-beta", "url": "…", "sha256": "…", "notes": "…" }
}
```

- Можно без каналов — один объект `{version, url, sha256, notes}`.
- Относительная ссылка считается от адреса манифеста.
- **Без `sha256` пакет не устанавливается.** Скачанный файл с другой суммой отклоняется.
- Автопроверка — раз в сутки. О новой версии пишется запись в журнале службы и уходит письмо (событие «Обновления» в разделе «Почта и уведомления»).
- Используйте HTTPS; http — только во внутренней доверенной сети.

### 4.2. Установка сервера

Кнопка «Установить vX.Y.Z» и подтверждение. Дальше:

1. Служба ещё раз сверяет пакет. Затем передаёт его установщику — копии **прежней** программы, запущенной вне службы (`systemd-run`; под OpenRC — отдельный сеанс). Перезапуск службы установщик не останавливает.
2. Установщик:
   - сохраняет `/opt/hopebackup/hopebackup.prev` и прежний комплект `/opt/hopebackup/dist.prev`;
   - ставит новую программу и комплект;
   - перезапускает `hopebackup-server`.
3. Установщик до 90 секунд ждёт, пока `/api/health` ответит **новой** версией.
   - Не ответила — возвращает прежнюю программу и комплект и снова перезапускает службу.
   - Итог: «Откат выполнен», служба работает на прежней версии.

Ход установки виден на странице: загрузка, проверка, замена программы, перезапуск. Во время перезапуска панель несколько секунд недоступна. После установки обновите страницу браузера (Ctrl+F5) — загрузится новая версия панели.

В журнал аудита записываются:

- запуск установки и её итог (установлено или не установлено — с причиной);
- загрузка и удаление пакета;
- смена источника обновлений.

Журнал установщика: `journalctl -t hopebackup-update`; под OpenRC — `/var/lib/hopebackup/server/updates/apply.log`.

### 4.3. Агенты

Блок «Агенты» показывает для каждого агента:

- сборку (`x86_64-gnu`, `aarch64-musl`…);
- версию: устаревшая — жёлтым;
- ход последнего обновления.

«Обновить устаревшие» запускает обновление всех агентов на связи, которые старее сервера; кнопка в строке — одного агента. Агент обновляется до версии **сервера управления**, поэтому сначала установите новую версию на сервер: пока загруженный пакет новее сервера, кнопок «Обновить» у агентов нет, и над таблицей это сказано. Как обновляется агент:

1. Агент скачивает с сервера управления сборку своей архитектуры из комплекта.
2. Сверяет SHA-256, проверяет запуском `--version` и отправляет итог задания.
3. Его установщик сохраняет `hopebackup.prev`, ставит новую программу и перезапускает `hopebackup-agent`.
4. Установщик до 2 минут ждёт, пока новая версия выйдет на связь с сервером управления. Не вышла — сам возвращает прежнюю и перезапускает службу.

Агент, на котором идут задания, не обновляется — повторите позже.

Агенты до 0.8.1 обновляются скриптом или кнопкой «Установить агента» в разделе «Серверы и ВМ»: она ставит программу из комплекта сервера, не трогая подключение агента.

Журнал установщика агента: `journalctl -t hopebackup-update` на машине агента; под OpenRC — `/var/lib/hopebackup/updates/apply.log`.

### 4.4. Принимающие узлы управления

На активном узле в «Обновлениях» есть блок **«Узлы управления»**: версия каждого принимающего узла и кнопка
**«До vX»** — обновить его до версии активного. Активный собирает архив выпуска из своей программы и комплекта
сборок и передаёт его узлу (через коннектор узла, если он задан), подписав общим ключом кластера с адресатом и
временем. Принимающий узел проверяет пакет как обычную загрузку (контрольные суммы сборок, архитектура, версия —
только новее своей), ставит его и перезапускается; при сбое — откат, как при обновлении из своей панели.
Порядок: сначала активный узел (кнопка «Установить» выше), затем принимающие, затем агенты.
Если на той же машине работает узел хранения (`hopebackup-node`), он перезапускается новой программой вместе
с сервером управления.

Узлы версии старше 0.8.14 этого не умеют: один раз обновите такой узел в его собственной панели (загрузка архива
выпуска) или скриптом. На принимающем узле можно и сейчас обновиться самостоятельно, загрузкой архива.

## 5. Скриптом установки

1. Из `bin/release` положите на сервер, например в `/tmp`, архив `hopebackup-<версия>-linux.tar.gz` и `hopebackup-install.sh`.
2. От root запустите установку с **той же ролью** — это и есть обновление:

   ```sh
   sh /tmp/hopebackup-install.sh server     # сервер управления (и принимающий узел)
   sh /tmp/hopebackup-install.sh node       # узел площадки
   sh /tmp/hopebackup-install.sh agent      # агент: подключение к серверу уже есть — токен не нужен
   sh /tmp/hopebackup-install.sh status     # что установлено и работает ли
   ```

Что делает скрипт при обновлении:

- сверяет контрольные суммы и выбирает сборку для машины;
- сохраняет прежнюю программу в `/opt/hopebackup/hopebackup.bak.<время>` (три последние);
- ставит новую;
- серверу обновляет комплект сборок;
- оставляет порт службы прежним;
- перезапускает службу.

Токены узла (`node.json`), подключение агента (`agent.json`) и данные сервера не меняются.

**С Windows (PuTTY):** `C:\HopeBackup\_deploy\deploy.cmd <IP> <пользователь> server` (или `node`, `agent`). Повторная установка той же роли — обновление.

**Агенты по SSH из панели:** «Серверы и ВМ» → машина → «Установить агента». Программа ставится из комплекта сервера, прежняя сохраняется как `hopebackup.bak.*`, служба перезапускается.

## 6. После обновления

- «Обновления»: текущая версия сервера; в блоке «Агенты» нет устаревших.
- «Агенты»: все на связи, версии совпадают с сервером.
- «Площадки» → «Проверить»: узлы и хранилища доступны.
- Внеочередная копия одного экземпляра — работает ли цепочка «агент → площадка».
- При обновлении с версий, где панель была на порту 7543: см. раздел 5 «Установки». Агенты сами перейдут на 4443, затем старый порт убирается.

## 7. Откат на прежнюю версию вручную

Автоматический откат срабатывает, если новая версия не запустилась. Если она запустилась, но вас не устраивает:

1. **Из панели.** Загрузите архив прежней версии и установите его. Панель предупредит, что это понижение версии.
2. **На сервере:**

   ```sh
   sudo systemctl stop hopebackup-server
   sudo cp -p /opt/hopebackup/hopebackup.prev /opt/hopebackup/hopebackup     # после обновления из панели
   # или: sudo cp -p /opt/hopebackup/hopebackup.bak.<время> /opt/hopebackup/hopebackup   (после скрипта)
   sudo systemctl start hopebackup-server
   ```

   Для агента — то же со службой `hopebackup-agent`. Под OpenRC: `rc-service <служба> stop|start`.

Прежняя версия читает каталог новой, но не знает её новых разделов. Ничего не потеряется, если вернуть и каталог из копии, снятой перед обновлением (раздел 3):

```sh
sudo systemctl stop hopebackup-server
sudo tar xzf /root/hopebackup-server-<дата>.tgz -C /var/lib/hopebackup
sudo systemctl start hopebackup-server
```

Всё, что изменили в панели после обновления, при этом откатится. Копии на площадках не затрагиваются.

## 8. Если что-то пошло не так

| Сообщение или признак | Что делать |
|---|---|
| «Служба работает не под systemd и не под OpenRC — установка отсюда недоступна» | Обновите скриптом `hopebackup-install.sh` (раздел 5) |
| «Пакет версии … старше 0.8.1» | Из панели ставятся версии с разделом «Обновления»; более старую — скриптом |
| «Контрольная сумма … не совпадает» | Архив повреждён при копировании или подменён: возьмите его заново и сверьте с `SHA256SUMS` |
| «Установщик не запустился за 60 секунд» | Проверьте `journalctl -t hopebackup-update` и наличие `systemd-run`; повторите установку |
| «Откат выполнен» | Новая версия не ответила за 90 секунд (агент — не вышел на связь за 2 минуты). Причина — `journalctl -u hopebackup-server` (`hopebackup-agent`) за время установки. Служба работает на прежней версии |
| «Новая версия не запустилась, и откат не удался» | На машине: `systemctl status hopebackup-server`, журнал службы; верните `/opt/hopebackup/hopebackup.prev` вручную (раздел 7) |
| У агента «нет в комплекте» | На сервере нет сборки для архитектуры агента: установите сервер из полного архива выпуска (не одной программой) |
| Агент не обновляется: «на агенте выполняются задания» | Дождитесь окончания копии или восстановления на нём и повторите |
| После обновления панель выглядит по-старому | Обновите страницу браузера с очисткой кэша (Ctrl+F5) |
